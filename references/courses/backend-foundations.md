# ⑭ 后端基础：API、数据与上线

状态：beta

## 唯一承诺

学生理解"不能只信浏览器的事"为什么必须由后端承担，能设计一个最小 API、说清数据存哪、谁能访问，并把服务部署到真实可访问的地址。

## 教学节点

1. 前后端边界：先读 `../lessons/shared/web-product-foundations.md` 的一张链路图，回答"这件事为什么不能放前端"（秘密、权限、持久化、多端共享）；
2. API 设计：资源与动词、请求体与响应体、JSON 契约；让 Agent 先写接口约定再写实现；请求异常时读 `../lessons/shared/http-status-codes.md`；
3. 服务端框架按需选型：Node（Express/Fastify）、Python（FastAPI）或其他，由 Agent 按学生环境和项目调查后提出最小方案，学生拍板，不统一指定；
4. 数据持久化：读 `../lessons/shared/database-and-data-authority.md`，画出数据权威源；从文件/SQLite 起步，确有共享需求再升级；
5. 鉴权与密钥：读 `../lessons/shared/safety-and-secrets.md`；环境变量与 `.env`、前端永不可见的秘密、登录与权限的区别；
6. 部署与环境：构建产物 vs 长驻进程、端口、环境变量在部署平台的配置、日志在哪里看；部署后真实访问验收。

## 铁律与证据

- 前端校验不当作安全；密钥不进前端、不进 Git；
- 验收必须包含：真实 HTTP 请求的成功与失败响应、数据库真实读写、一次部署后的外部可访问访问；
- 完成需要一张链路图（用户动作 → API → 数据）、一份接口约定、鉴权与密钥处理说明、部署后的真实访问证据；
- 本课程正在拆分独立 lesson；现阶段按节点讲授并做最小实验。
