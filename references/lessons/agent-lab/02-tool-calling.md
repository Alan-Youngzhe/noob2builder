# 给 Agent 一个真实工具

## 目标

设计一个边界明确、结果可观察的工具，并让 Agent 在需要时正确调用。

## 讲授

一个好工具要有：清楚名称、输入 schema、输出结构、失败格式、权限边界和幂等策略。工具越大越万能，模型越难判断何时调用，也越难测试。

先选择低风险任务，例如读取公开天气、转换本地文本格式、查询一个只读数据源或执行确定性计算。第一件工具不要碰支付、删除、生产写库和敏感数据。

## 实验

1. 定义一个真实任务和“不调用工具无法可靠回答”的情况。
2. 让 Agent 查看目标平台或库的当前官方文档，不凭记忆写接口。
3. 选择最轻实现：现有 CLI、简单脚本、MCP 或平台 Function Calling 均可。
4. 定义正常输入、缺少参数、无结果、超时和外部失败。
5. 实际调用一次，查看结构化输入和输出。
6. 再给一个不需要工具的问题，确认 Agent 不滥用工具。

## 证据

工具定义、一次成功调用、一次失败结果和一次“不该调用时没有调用”的记录。密钥不得写入仓库或证据卡。
