# 先给项目做体检，别急着改

## 目标

学生能在一小时内摸清一个自己写但已经不敢碰的项目：它实际能干什么、结构长什么样、风险在哪、哪些地方连自己都说不清。

## 讲授

"不敢改"的本质是**你不知道改了会碰坏什么**。所以第一步不是重构，是把未知变成清单。

体检分四张表，顺序不能反：

**一、行为清单**——这个项目对用户承诺了什么。逐条写成可验证的句子："用户提交表单后，收到一封确认邮件。"不是"有邮件功能"。这份清单就是你事后补 PRD 的原料。

**二、结构地图**——代码怎么组织的、入口在哪、数据从哪进哪出。让 Agent 生成，但你要能指着说"这个我认得"。它认错的地方，就是最需要注意的地方。

**三、风险清单**——按"坏了有多疼"排序，不按"改起来有多难"。优先级基本固定：**钱 > 数据 > 权限 > 删除 > 外部副作用 > 显示效果**。一个按钮颜色错了没人受伤，一个删除接口没校验权限能毁掉全部数据。

**四、未知清单**——你自己都答不上来的问题。"这段代码是干嘛的"、"这个配置项还有用吗"、"这个定时任务谁在跑"。**这张表最有价值，也最容易被跳过**，因为写它让人不舒服。

有一条硬规矩：**体检阶段不改代码。**发现问题就记下来，一改就会开始连锁反应，体检做不完了。

涉及持久化、多进程或多端时，插入 `../shared/database-and-data-authority.md`，把进程和数据流画出来——这类项目最常见的隐藏事故就是数据权威源分裂。

常见误区：一边看一边顺手改；只体检代码不体检部署和数据；把 Agent 生成的结构图当成事实而不核对。

## 实验

1. 让 Agent 读一遍仓库，输出结构地图和它推断的核心行为，**你逐条核对**，标出它猜错的地方；
2. 看真实历史，找出最近改动最频繁的文件——它们通常就是风险集中区：
   ```bash
   git log --since="6 months ago" --name-only --pretty=format: | sort | uniq -c | sort -rn | head -20
   ```
3. 把行为清单写成可验证的句子，至少 5 条；
4. 按"钱、数据、权限、删除、外部副作用"扫一遍代码，列出高风险位置；
5. 写未知清单，**至少写 5 条你自己答不上来的问题**——写不出来说明你还没认真看；
6. 检查有没有密钥进过 Git、有没有生产数据在本地。

## 常见误区

- Agent 说"这个项目结构清晰"是废话，要它指出具体的入口、数据流和可疑处；
- 改动频繁的文件不一定写得差，但一定是风险集中的地方；
- 未知清单上的每一条，后面都要么变成注释、要么变成测试、要么被删掉。

## 证据

四张清单落成文件；第 2 步的真实命令输出入档；未知清单不少于 5 条；体检期间**零代码改动**（`git status` 干净可作为证据）。
