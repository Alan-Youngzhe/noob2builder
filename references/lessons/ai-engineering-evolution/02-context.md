# 第二层：Context 解决"它不知道"

## 目标

学生能判断该往 Context 里放什么、不放什么，并知道"塞得越多越好"为什么是错的。

## 讲授

上一节分出来的第一类错误——**它不知道**——归这一层管。

Context 层解决的是：**把任务需要的正确资料、状态、工具描述和约束准备好。**注意"正确"两个字，不是"全部"。

该放的四类：

1. **任务需要的事实**：相关文档、历史记录、当前状态；
2. **判断标准**：什么算对、什么算错。你自己都说不清的标准，模型也猜不出来；
3. **可用的工具**：它能调什么、参数是什么；
4. **边界**：什么不能做、什么必须问人。

**不该放的：**

- 与本次任务无关的资料。它不是中性的，会稀释注意力，让模型在错误的方向上找依据；
- 冗长的历史对话。多数时候一份摘要比全文更有效；
- 互相冲突的规则。两条打架时模型的行为不可预测。

**"塞满就行"为什么是错的**——两个具体原因：

- **钱**：每一轮都要重发，见 `../ai-map/02-token-and-cost.md`；
- **准确率**：无关内容多了之后，模型更容易引用到不该引用的部分。长上下文里的信息也不是均匀被使用的，位置靠前和靠后的通常被利用得更好，埋在中间的容易被忽略。所以**重要的东西别放在正中间**。

**这一层最实用的一条工程判断**：资料不多时直接读文件进 Context，比搭 RAG 更准也更简单。RAG 是为了应付"资料超过 Context Window"才存在的，见 `../llm-agent/05-search-and-rag.md`。

常见误区：把整个知识库都塞进去；把判断标准留在自己脑子里；规则文件越写越长且互相矛盾。

## 实验

继续用上一节那个任务和那 5 个样本：

1. 找出上一节"它不知道"那类错误，逐条问：它缺的是哪份资料、哪条标准？
2. 只补 Context——把缺的资料和判断标准加进去，**提示词一个字不改**；
3. 跑同样 5 个样本，和基线对比正确率；
4. **做一次减法实验**：故意多塞进去一份无关资料，再跑一次，观察正确率变化和 token 增量；
5. 把判断标准单独写成一份文件（后面 Harness 层要用）；
6. 记录这一层的收益：正确率提升了多少、token 增加了多少。

## 常见误区

- 补 Context 和改提示词要分开做，一起改就不知道是哪个起了作用；
- 第 4 步如果正确率没降，也要记录 token 涨了多少——那是实打实的成本；
- 判断标准写不出来时，就说明这个任务你自己还没想清楚。

## 证据

补 Context 前后的正确率对比、token 用量对比、第 4 步减法实验的结果，以及一份独立的判断标准文件。
