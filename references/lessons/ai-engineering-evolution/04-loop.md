# 第四层：Loop 什么时候值得，什么时候是烧钱

## 目标

学生能判断一个任务适不适合让 Agent 自动循环迭代，并会给循环设止损线。

## 讲授

有了验证器，就可以让模型"做 → 检查 → 改 → 再检查"一直转下去，直到通过。这就是 Loop。

**但 Loop 不是万能的。**适合 Loop 的任务必须同时满足三个条件：

1. **可重复**——同样的操作可以做很多次，不会产生不可逆的副作用。发邮件、扣款、删数据都不能随便循环；
2. **可评分**——有一个自动的验证器能判断好坏。没有验证器的循环只是在让模型自言自语；
3. **可恢复**——失败了能回到上一个状态。代码有 Git，数据有备份，这些才敢循环。

三条缺一条，就别循环。

**"循环十次"为什么不自动提升质量：**

- 如果验证器有盲区，循环会**针对验证器优化**，而不是针对真实目标。它会找到验证器的漏洞然后钻进去——测试全过但行为是错的；
- 如果模型从根本上不会这件事，循环十次只是用十倍的钱得到同样错的结果；
- 每一轮都带着前面所有的尝试，Context 越来越长，越到后面越贵也越乱。

**止损线必须提前定：**最多几轮？几轮没进展就停？成本上限多少？达到任意一条就停下来交给人。一个实用的经验值是：**同一个错误连续出现两次，就停。**第三次大概率也一样。

真实的例子你每天都在用：Claude Code "改代码 → 跑测试 → 看报错 → 再改"就是一个 Loop，验证器是测试套件。它之所以能用，正是因为代码满足上面三条：可重复、有测试可评分、有 Git 可恢复。

常见误区：以为循环次数越多越好；在没有验证器的任务上循环；不设上限。

## 实验

继续用那个任务：

1. 检查它是否满足三个条件，逐条写结论；如果有一条不满足，写清楚为什么，然后**只做模拟**；
2. 设止损线：最多几轮、连续几次同样错误就停、成本上限；
3. 把"生成 → 验证 → 带着错误重试"做成循环，跑同样 5 个样本；
4. 记录每个样本用了几轮、最终是否通过、花了多少 token；
5. **人工复核循环通过的输出**——验证器说通过的，是不是真的对？如果发现"验证通过但实际错误"，这就是循环在钻验证器的空子，记下来；
6. 对比：Loop 相比上一层，正确率提升了多少，成本增加了多少，值不值？

## 常见误区

- 第 5 步是本节最重要的一步，不能省；
- 如果 Loop 相比 Harness 层几乎没有提升，结论就是"不需要 Loop"，这是合法的结论；
- 有副作用的任务要循环，必须先把副作用隔离到循环之外。

## 证据

三个条件的逐条判断；止损线设置；每个样本的轮数、结果和 token；人工复核结果，特别是"验证通过但实际错误"的案例；一句明确结论——这个任务值不值得用 Loop。
