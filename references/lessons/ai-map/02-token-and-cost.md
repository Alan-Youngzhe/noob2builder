# 钱是怎么花掉的：token、计价与 Context Window

## 目标

学生能看懂一份模型定价表，估算自己一次对话大概花了多少，并知道账单变贵时该去动哪里。

## 讲授

**token 是计价单位**，不是字也不是词。够用的量级：英文约 4 个字符 ≈ 1 token，中文 1 个汉字 ≈ 1～2 token，`Hello, world!` 约 4 个 token。生成机制见 `../llm-agent/01-next-token.md`，这里只关心花钱。

读定价表要抓住三点：

1. **单位通常是"每百万 token 多少美元"**，看到 `$3 / MTok` 就是每一百万输入 token 三美元；
2. **输入和输出分开计价，输出明显更贵**，常见是输入的 3～5 倍。所以"让它别写那么长"是真能省钱的；
3. **缓存命中的输入更便宜，写入缓存则略贵**。具体倍率和当前价格以现场查证为准，不要背。

**Context Window** 是一次请求能装下的 token 上限，主流模型目前在 20 万 token 这个量级，具体数字随版本变。它和费用是两件事但连在一起：

- 上限管的是**装不装得下**，超了会被截断或报错；
- 费用管的是**每次装了多少**，因为每一轮都要把历史重发一遍。

这就是"聊得越久越贵"的真正原因——不是变聪明了要加钱，是第 20 轮那次请求把前 19 轮全带上了。一次长对话的成本大致是每轮输入量的累加，**呈平方级增长而不是线性**。

省钱的动作按性价比排序：开新会话（最有效，直接清掉历史）、把长资料存成文件按需读取而不是整段贴进来、把稳定内容放前面利用缓存、要求简短输出、任务简单时换更便宜的小模型。

常见误区：以为 Context Window 大就可以随便塞（贵，而且无关内容会稀释注意力）；以为免费额度等于没成本；以为"清空对话"按钮一定真的清掉了历史（要看客户端实现）。

## 实验

1. 让 Agent 查出你当前在用的模型的**现价**和 Context Window 上限，写下查证日期；
2. 估算你今天这次会话已经消耗了多少 token、大概多少钱，Agent 给不出准确值时给量级并标注为估算；
3. 找一段长资料，对比两种做法的 token 差异：整段贴进对话 vs 存成文件让 Agent 按需读取；
4. 把同一个问题分别问一次要求"详细展开"和一次要求"三句话内回答"，对比输出 token；
5. 在 `MY_AI_MAP.md` 里加一节：我的常用模型、单价、上限、我这个月大概的用量。

## 常见误区

- token 数在不同厂商的切分方式下不完全一样，跨厂商比价要用同一段文本实测；
- 上下文塞满不等于用满价值，检索到的无关内容会降低回答质量；
- 价格变动频繁，笔记里的数字必须带日期。

## 证据

`MY_AI_MAP.md` 中有一节真实的成本记录，含查证日期；学生能说出自己这次会话里最占 token 的是哪一块，以及下次准备怎么减。
