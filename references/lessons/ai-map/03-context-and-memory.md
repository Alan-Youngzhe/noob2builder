# Context 和记忆不是一回事

## 目标

学生能分清"这次带过去的"和"跨会话留下的"，并能指出自己机器上真正承担记忆功能的那几个文件。

## 讲授

**Context** 是这一次请求实际发出去的全部内容：规则、历史、资料、你这句话。请求结束，模型什么都不留。

**Memory** 是跨会话还在的东西。它不在模型里，**在你的硬盘上**。所谓"AI 记住了我的习惯"，实现上永远是同一件事：某个程序把某个文件读出来，塞进了这次的 Context。

在 Claude Code 里，这几个文件就是记忆的实体，可以直接打开看：

| 文件 | 作用 | 生效范围 |
|---|---|---|
| `~/.claude/CLAUDE.md` | 你的全局规则 | 所有项目 |
| 项目根目录的 `CLAUDE.md` | 这个项目的规则 | 当前项目 |
| `~/.claude/skills/<名字>/SKILL.md` | 某类任务的做法说明 | 触发时加载 |
| `~/.claude/settings.json` | 权限、模型、环境变量等配置 | 全局 |
| `~/.noob2builder/me.json` | 本校的学习存档 | 本课程 |

**这就是"记忆"的全部真相：一堆纯文本文件，加上一段把它们读进 Context 的逻辑。**理解了这点，很多困惑会立刻消失——它"忘了"某件事，去查那件事写在哪个文件里、这次有没有被读进来，而不是琢磨模型出了什么问题。

另一个必须分开的是**缓存**。缓存省的是重复计算，内容仍然要完整发过去；缓存过期只会变慢变贵，不会导致它"忘事"。机制细节见 `../llm-agent/03-context-memory-cache.md`。

三者一句话区分：**Context 是这次带了什么，Memory 是下次还能带什么，缓存是这次带得快不快。**

常见误区：把"记忆功能"当成模型属性；以为写进 `CLAUDE.md` 的东西模型"学会了"（它只是每次都被重新读一遍）；以为删掉界面上的对话就等于删掉了记忆（要删的是文件）。

## 实验

1. 依次打开上表里你机器上真实存在的每一个文件，读一遍内容，说出它在管什么；
2. 往 `~/.claude/CLAUDE.md` 加一条能看出效果的小规则（例如某种回复格式），**新开一个会话**验证是否生效；
3. 再把它删掉，新开会话验证效果消失——这一步证明的是"文件 → Context"这条链路；
4. 检查这些文件里有没有 API Key、手机号、客户信息，有就清掉，理由见 `../shared/safety-and-secrets.md`；
5. 在 `MY_AI_MAP.md` 里加一节：我的记忆都存在哪几个文件、各管什么、哪些内容不该写进去。

## 常见误区

- 规则写得越多不等于越好用，互相冲突时行为会变得难以预测；
- 项目级规则和全局规则可能打架，出现怪行为时先看这两处；
- 记忆文件会被完整读进 Context，写太长既费钱又稀释注意力。

## 证据

完成一次"加规则 → 新会话生效 → 删规则 → 新会话失效"的完整验证，两次会话的真实表现入档；`MY_AI_MAP.md` 中列出学生本机真实的记忆文件清单。
