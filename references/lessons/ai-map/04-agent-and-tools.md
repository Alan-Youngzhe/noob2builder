# Agent 和聊天机器人差在哪

## 目标

学生能说出一个程序凭什么算 Agent，看懂它干活时屏幕上滚过的那些东西分别是什么，并知道权限卡在谁手里。

## 讲授

聊天机器人**只输出文字**，做不做由你决定。Agent 的区别只有一条：**它能真的动手，并且看到结果之后会自己决定下一步。**

拆开来是四个必要零件，缺一个就不算：

1. **模型**——负责判断下一步该干什么；
2. **工具**——读文件、写文件、跑命令、发网络请求；
3. **循环**——执行完看结果，决定继续还是收工；
4. **停止条件**——什么时候算完成、什么时候该放弃。

第 4 条最容易被忽略，也最容易出事：没有停止条件的 Agent 会在一个修不好的问题上反复试，把钱和你的耐心一起烧光。

必须记牢的一点：**模型不能操作电脑，宿主程序才能。**模型只会输出一句结构化的"我想调用 `read_file`，参数是这个路径"，真正去读的是 Claude Code 这个本地程序。所以：

- **权限在宿主手里**，不在模型手里。模型请求删除文件，宿主可以拒绝，也可以先问你；
- 你在 Claude Code 里看到的"是否允许执行"弹窗，就是宿主在行使这个权力；
- 出了事该查的是宿主的权限配置（`~/.claude/settings.json`），不是模型。

屏幕上滚过的内容基本就三类，看懂了就不慌：模型的判断（文字）、工具调用（工具名 + 参数）、执行结果（命令输出、文件内容、报错）。循环的机制细节见 `../llm-agent/06-tools-and-agents.md`，本节只要求能认出来。

常见误区：以为 Agent 越自动越好（无人看管的循环最贵也最危险）；以为它"想删你的文件"（它只是提出请求）；以为报错就是它坏了（报错进 Context 后它会换路，这是正常工作）。

## 实验

1. 给当前 Agent 一个必须动手的小任务，全程盯着屏幕，把滚过的内容按三类标注一遍；
2. 数一数它一共调用了几次工具、循环了几轮；
3. 故意给一个它会失败的任务（比如读一个不存在的文件），观察它拿到报错之后怎么调整——这是"循环"最直观的演示；
4. 打开 `~/.claude/settings.json` 看权限配置，找出哪些操作是自动允许的、哪些会弹窗问你；
5. 让学生说出：如果这次它跑偏了，你在哪一步能拦住它？

## 常见误区

- 让 Agent 一次做十件事，出问题时你分不清是哪一步坏的，小切片更快；
- "它自己跑了二十轮还没好"通常意味着任务描述有问题，不是它不够努力；
- 危险操作（删除、覆盖、`sudo`、推送）第一次遇到必须加载 `../shared/safety-and-secrets.md`。

## 证据

一次真实任务的完整记录，学生能逐段指出哪里是模型判断、哪里是工具调用、哪里是执行结果，并说出自己能在哪一步介入。
