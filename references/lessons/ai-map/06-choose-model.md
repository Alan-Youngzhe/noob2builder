# 选型：六个维度，和一条给小白的默认答案

## 目标

学生能用六个维度比较模型，而不是跟着榜单和热搜换；同时知道在自己还没有判断力之前，默认选什么最省事。

## 讲授

先给默认答案，免得纠结：**刚开始就用你手上 Agent 的默认主力模型，别折腾。**选型的收益在你有了真实用量和真实痛点之后才出现，一开始换来换去纯属浪费时间。

真要比的时候，比这六个维度：

1. **能力**——它能不能做对这类任务。注意分任务类型：写代码、长文档理解、多轮工具调用、中文写作，强弱排序并不一样；
2. **成本**——每百万 token 多少钱，输入输出分开算，见 `02-token-and-cost.md`；
3. **速度**——首字延迟和生成速度。交互式场景对延迟敏感，批量任务不敏感；
4. **Context 上限**——一次能装多少。要处理整个代码库还是回答一个短问题，需求差一个数量级；
5. **工具能力**——能不能稳定地调用工具、按格式输出。做 Agent 时这一条比"聪明"更重要，一个稍弱但工具调用稳定的模型，实际效果常常更好；
6. **可用性与合规**——限流、稳定性、数据是否可以出境、能否私有部署。企业场景下这一条经常直接否决前五条。

三条实战判断：

- **榜单分数和你的任务基本没关系。**唯一有意义的评测是拿你自己的真实任务跑一遍，同一组输入，比较输出；
- **不要一个模型用到底。**便宜小模型做批量分类和格式转换，贵模型做需要判断的活，是常见组合；
- **换模型不等于换服务商。**同一个模型可以走官方 API、云平台或中转，数据路径完全不同，见 `../llm-agent/04-data-path.md`。

常见误区：以为参数量越大越好；以为最新版本一定更适合你的任务；以为贵的模型在所有任务上都赢。

## 实验

1. 从自己真实工作里挑 3 个代表性任务（其中至少一个是你每天都干的）；
2. 用当前模型跑一遍，把输出存下来；
3. 换一个明显更便宜或更快的模型跑同样三个任务，输出并排对比；
4. 逐个判断：哪些任务其实用便宜的就够了？哪些必须用贵的？说出依据是什么；
5. 完成 `MY_AI_MAP.md` 终版，加上最后一节：我的任务清单、各自选哪个模型、为什么；
6. 让一个没参与过这次对话的 Agent 只读 `MY_AI_MAP.md`，复述一遍你的技术栈和选择理由。它说错的地方就是你没写清的地方。

## 常见误区

- 只比一次结果不足以下结论，同一任务至少跑两三次再看；
- 便宜模型省下的钱可能被返工次数吃掉，算总账不算单价；
- 记录选型结论时必须写日期，模型迭代很快，三个月后结论可能就不成立了。

## 证据

`MY_AI_MAP.md` 终版，包含五层地图、成本记录、记忆文件清单、已装扩展清单和任务-模型对照表；第 3 步的真实对比输出入档；第 6 步的交接测试结果入档，含 Agent 复述错的地方和你的修订。
