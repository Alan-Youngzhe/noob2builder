# 让 Agent 调查技术方案

## 目标

不固定 Node.js、Python、Supabase 或 Vercel，让 Agent 围绕当前作品推荐最小方案。

## 讲授

技术选型不是工具排行榜。先看：作品形态、数据是否要保存、是否多人使用、是否需要登录、怎样交付、预算、现有环境和做错后的代价。

Agent 的推荐必须使用统一格式：

```markdown
## 推荐方案
## 为什么适合当前目标
## 暂时不需要什么
## 一个备选方案
## 第一段可验收成果
## 当前风险与需要查证的文档
```

涉及快速 Web 原型时可以提 Lovable 或 baoyu-design；需要设计协作时可提 Figma/Pencil MCP；需要数据库和部署时可提 Supabase/Vercel，但必须说明替代项和是否真的需要。

## 实验

让 Agent 先检查当前目录和可用环境，再查对应工具的当前官方文档。至少比较两个方案，但只推荐一个。学生根据成本、可理解性和交付方式拍板。

## 证据

`DECISIONS.md` 包含推荐、理由、非目标、备选和第一刀；没有因为“热门”自动加入登录、数据库或复杂框架。
