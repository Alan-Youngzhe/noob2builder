# 把“完成”写成证据

## 目标

用具体样例、边界、日志、diff、测试和用户行为验收，不接受 Agent 自报完成。

## 讲授

验收标准描述可观察行为：“当输入 X 时，系统返回 Y”；不是“体验流畅”“代码优雅”。至少覆盖正常输入、边界输入和失败路径。

调试顺序：稳定复现 → 保存错误原文 → 判断发生层级 → 一次只改一个假设 → 重跑同一个失败场景 → 再跑相邻回归。连续让 Agent“再修一下”会不断污染代码和 Context。

按风险选证据：视觉问题真实浏览器验；明确逻辑写断言；数据库、权限、删除等再加人工 Review。测试文件存在不算测试运行。

## 实验

1. 生成 `ACCEPTANCE.md`，至少三个 Given/When/Then 样例。
2. 让 Agent 主动提出一个可能的错误假设。
3. 对当前项目执行最便宜的真实验证。
4. 如果失败，完成一次“复现—根因—修复—重测”。
5. 记录机器无法证明的剩余风险。

## 证据

真实命令或行为结果、一次错误假设修正和未验证清单。没有执行的检查必须标记未验证。
