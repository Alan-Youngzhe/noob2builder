# 终端、命令与进程：Agent 的手在哪里

## 目标

学生不再把终端当成"黑客界面"，能读懂一条命令由什么组成，知道什么是进程、它为什么会一直占着终端不还给你，以及怎样安全地停掉它。

## 讲授

终端就是一个**逐条接收命令、返回文本**的界面。Agent 操作电脑主要靠它。一条命令的结构通常是：

```text
命令  选项      参数
ls    -la      ~/Documents
```

命令执行完会返回一个**退出码**：0 表示成功，非 0 表示失败。这是判断"到底成没成"最便宜的机器证据——比 Agent 说"已完成"可靠得多。

有两类命令要分开理解：

- **一次性命令**：跑完就结束，比如 `ls`、`git status`；
- **长驻进程**：启动后一直运行，比如开发服务器。它会占住终端不返回提示符，这不是卡住，是正常工作。停止它用 `Ctrl + C`。

**权限**决定一条命令能不能动某个文件。`sudo` 意思是"用管理员身份执行"，它会绕过保护，因此不是万能补丁而是危险信号：Agent 建议加 `sudo` 时，先问清为什么这一步需要管理员权限。

常见误区：把"终端没反应"当成失败（其实是长驻进程在跑）；看到红色输出就以为是崩溃（很多是警告）；用 `sudo` 解决一切权限报错。

## 实验

1. 让 Agent 执行一条一次性命令，然后立刻查看退出码（`echo $?`），再故意执行一条会失败的命令，再看一次退出码，对比两个数字；
2. 启动一个最小的本地静态服务器（比如 `python3 -m http.server 8000`），观察终端不再返回提示符；
3. 另开一个终端窗口，用 `curl -I http://localhost:8000` 确认它真的在服务；
4. 回到第一个窗口按 `Ctrl + C` 停止，再 `curl` 一次，观察这次失败的样子；
5. 让 Agent 解释第 4 步的失败信息属于哪一类：命令错、服务没起、网络不通还是地址写错。

## 常见误区

- 退出码 0 只证明命令执行成功，不证明业务结果正确；
- 关掉终端窗口通常会一起杀掉它启动的长驻进程；
- 首次遇到危险命令（删除、覆盖、`sudo`、改系统配置）必须先加载 `../shared/safety-and-secrets.md`。

## 证据

学生能独立完成一次"启动服务 → 确认在跑 → 停止 → 确认停了"的闭环，并说出两次 `curl` 结果的区别来自哪里。终端输出入档。
