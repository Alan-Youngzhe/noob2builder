# 一个地址是怎么找到一台机器的：URL、DNS、IP 与端口

## 目标

学生能拆开一个 URL 的每一段，说清 `localhost:3000` 里的每个部分是什么意思，并解释为什么换个端口就打不开了。

## 讲授

拆开一个地址：

```text
https://  api.example.com  :443  /v1/users  ?page=2
协议       主机名            端口  路径        查询参数
```

- **协议**决定用什么方式通信，`https` 是加密的 `http`；
- **主机名**要先经过 **DNS** 翻译成 **IP 地址**（一串数字），才能真正找到机器。域名是给人记的，IP 是给机器用的；
- **端口**是同一台机器上的门牌号。一台机器可以同时跑很多服务，靠端口区分。`http` 默认 80，`https` 默认 443，所以平时不用写；
- **路径**和**查询参数**是给那台机器上的程序看的，决定返回什么内容。

`localhost` 是一个特殊主机名，永远指向**你自己这台机器**（IP `127.0.0.1`）。所以 `http://localhost:3000` 的意思是"我这台机器上 3000 号门后面的服务"。端口写错，就是敲错了门——门后面没人，自然打不开。

常见误区：以为 `localhost` 是某个网站；以为端口号可以随便改而地址还通；分不清"域名解析失败"和"服务没启动"，两者报错完全不同。

## 实验

1. 用 `ping example.com` 或 `nslookup example.com`，看到域名被翻译成 IP；
2. 启动上一节的本地服务器（记住它监听的端口）；
3. 依次访问三个地址，记录各自的结果和报错文字：
   - `http://localhost:<正确端口>`
   - `http://localhost:<随便一个没用的端口>`
   - `http://不存在的域名.example`
4. 让学生给这三个结果分类：哪个是服务没起、哪个是域名解析不了、哪个是正常；
5. 用 `lsof -i :<端口>`（macOS/Linux）看看到底是哪个进程占着这个端口。

## 常见误区

- 端口被占用时启动服务会失败，报错通常写 `address already in use`，解法是换端口或停掉占用的进程，不是重装环境；
- `127.0.0.1` 和 `localhost` 通常等价，但和你的局域网 IP（如 `192.168.x.x`）不是一回事，下一节会用到这个区别。

## 证据

学生能对着自己项目的启动日志，指出服务监听在哪个端口，并预测把地址里的端口改掉之后会发生什么，然后实际验证预测是否正确。
