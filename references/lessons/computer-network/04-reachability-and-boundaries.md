# 本地能跑不等于别人能访问：可达性、代理与边界

## 目标

学生能解释"我这里打得开，同事打不开"是怎么回事，知道公网访问需要什么，并对代理和合规边界有基本判断力。

## 讲授

这是小白做出第一个作品后最常撞的墙：**在自己电脑上跑起来了，把地址发给朋友却打不开。**

原因是 `localhost` 对每个人来说都指他自己那台机器。你发过去的 `http://localhost:3000`，在对方电脑上找的是对方的 3000 端口。

一个地址能不能被别人访问，取决于几层，从近到远：

1. **服务在跑吗**——进程是否存活、监听哪个端口；
2. **监听的地址对吗**——只监听 `127.0.0.1` 意味着只有本机能连，监听 `0.0.0.0` 才接受外部连接；
3. **同一个网络能到吗**——局域网内可以用你的内网 IP（`192.168.x.x`）互访；
4. **公网能到吗**——需要一个公网地址或隧道服务，家用网络默认不对外开放；
5. **对方的网络放行吗**——防火墙、公司网络、地区限制都可能挡住。

**代理**是把你的请求先发给中间的一台机器、再由它转发出去。它能解决访问不到的问题，但也意味着这台中间机器看得见你的流量。命令行工具、Agent 和浏览器可能各用各的代理设置，这就是"浏览器能开、`curl` 不行"的常见原因。

**边界**部分要说明白：绕过技术限制去访问受限资源、抓取明确禁止抓取的站点、把公司或客户数据发到未经授权的外部服务，这些不是技术难题而是责任问题。课程不提供绕过手段，遇到访问不了的资源，优先换合规的数据来源。

常见误区：把"本地跑通"当成"上线了"；把代理当成万能开关；以为 Agent 用的网络设置和浏览器一样。

## 实验

1. 启动本地服务，在自己的浏览器确认可访问；
2. 查出本机内网 IP（macOS `ipconfig getifaddr en0`），用手机连同一个 Wi-Fi 访问 `http://<内网IP>:<端口>`，记录成功或失败；
3. 如果失败，让 Agent 分层诊断：服务是否只监听 `127.0.0.1`？端口是否被防火墙挡住？
4. 把服务改成监听 `0.0.0.0` 再试一次，对比结果；
5. 让学生用一句话回答："要让完全不在这个网络里的人访问，还缺什么？"

无法真实制造第 2 步条件时（没有第二台设备），标记为**演练**，用讲解链路代替，存档写 `simulated`。

## 常见误区

- 把服务暴露到 `0.0.0.0` 意味着同网络的人都能访问，练习完记得关掉；
- 真正上线需要的东西（域名、公网地址、HTTPS 证书、部署平台）属于 ⑭ 后端基础，这里只要求能说清缺口在哪。

## 证据

学生能画出一条从"另一台设备"到"我的服务"的链路，并指出自己这次卡在哪一层。第 2、4 步的结果对比入档，失败也要如实记录。
