# Agent 更容易吃什么：格式、结构与输入方式

## 目标

学生能判断同一份信息用什么格式交给 Agent 更省事，理解"可提取、可修改、可 diff"这三个标准，并学会用语音输入降低提供 Context 的摩擦。

## 讲授

同样一份数据，格式不同，Agent 能做的事差别很大。判断标准就三条：

- **可提取**：不用猜就能取到具体字段；
- **可修改**：能精确改一处而不动其他地方；
- **可 diff**：改动前后能看出差了哪几行。

按这三条排队：

| 形式 | 可提取 | 可修改 | 可 diff |
|---|---|---|---|
| 截图 / 扫描件 | 需要识别，易错 | 几乎不行 | 不行 |
| PDF | 部分 | 差 | 差 |
| HTML | 可以，但夹杂大量无关标记 | 一般 | 一般 |
| Markdown | 好 | 好 | 好 |
| CSV | 表格数据最好 | 好 | 好 |
| JSON | 结构化数据最好 | 好 | 好 |

所以"把需求截图发给 Agent"通常不如"把同样的内容写成 Markdown"。这不是格式洁癖，是直接影响它能不能精确改动、你能不能看出它改了什么。

**输入方式**同理。小白提供 Context 时最大的摩擦是打字慢，于是把话说短，Agent 只好靠猜。用系统自带的语音输入把想说的完整说出来，哪怕啰嗦、有口误，信息量也远高于一句"帮我做个网站"。先说全，再让 Agent 复述整理，你修正——比一开始就压缩自己要好。

常见误区：以为发截图更省事（对方要先识别，还可能读错）；以为格式规整是给人看的（其实主要是给机器和 diff 用的）；以为提示词要写得短而精（早期阶段信息完整比精炼更重要）。

## 实验

1. 选一份学生手上真实的信息（一张表格、一份说明、一个页面）；
2. 分别以截图和纯文本/CSV 两种形式交给 Agent，让它提取同样三个具体字段，对比准确度和往返次数；
3. 让 Agent 修改其中一个字段，再让它说明"改了哪里"——观察哪种形式能给出精确答案；
4. 用语音输入完整口述一遍自己想做的东西（不少于一分钟），让 Agent 整理成结构化要点，学生逐条修正；
5. 对比第 4 步的产出和自己平时会打出来的那一句话，数一数多出了多少条有效信息。

## 常见误区

- 结构化不等于填满模板，空字段照实留空比编造好；
- 语音输入产生的错别字由 Agent 整理时纠正即可，不必先手动清理；
- 有些信息本来就只有截图（比如第三方后台），这时明确告诉 Agent 这是截图来源、可能识别错误。

## 证据

学生能说出自己项目里哪些资料应该转成 Markdown/CSV/JSON，并至少真实转换一份。第 4 步的语音口述整理稿入档。
