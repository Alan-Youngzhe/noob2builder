# brainstorming 发散、GrillMe 访谈与 PRD v0

## 目标

先用有限 brainstorming 发散值得做的问题，再通过需求访谈把选定方向压成第一版 PRD，根据作品动态决定需要学什么，而不是先学完整技术栈。

## 讲授

brainstorming 先产生 3–5 个候选问题或方向，并把灵感、事实、假设分开；GrillMe 再把选定方向逐个压实：用户、场景、行为、输入输出、范围、成功标准、约束和边界。对应 Skill 已安装时调用；未安装时导师执行同等流程。访谈不要求小白决定技术栈。

访谈结束先产出薄的 `PRD.md` v0。它是给 Design System 和原型探索的起点，不是不可修改的施工合同。至少包含：问题与用户、高层方案、目标、非目标、核心流程、成功标准、假设和开放问题。

同时生成一张初步项目地图，包含用户流程、数据、界面或入口、核心处理、交付方式和验证。每块只在需要时展开。

## 实验

1. 用 brainstorming 列出 3–5 个候选问题或方向，标记灵感、事实和假设。
2. 选定一个方向，让 Agent 复述已知事实和假设，从第一个未解决的需求分支开始访谈。
3. 每次只回答一个问题，直到范围和成功标准足够支持原型。
4. 生成 `PRD.md` v0。
5. 生成 `PROJECT_MAP.md`：

```text
用户 → 入口 → 输入 → 处理 → 输出 → 保存/交付 → 验证
```

6. 为节点标记：已有、需要现学、Agent 可完成、需要学生拍板、暂不需要。把秘密、个人数据、删除、写库、权限和付费服务标红。

## 证据

PRD v0 能给 Design System 和原型提供方向，项目地图能解释第一刀从哪里进入、在哪里结束；推测被标为假设，没有出现无关的技术全家桶。
