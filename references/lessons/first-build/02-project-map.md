# 生成个人项目地图

## 目标

根据学生作品动态决定需要学什么，而不是先学完整技术栈。

## 讲授

项目地图至少包含六块：用户流程、数据、界面或入口、核心处理、交付方式、验证。每块只在需要时展开。

Agent 先检查当前环境，再提出一个主方案、一个备选和暂不需要的内容：

- 静态内容可用简单网页或可分享文档；
- 本地自动化可用适合文件处理的脚本；
- 多人共享与持久化才考虑后端和数据库；
- Agent/Skill 项目需要上下文、工具、失败恢复和 Eval；
- 公开协作需要 GitHub、Issue 和 PR。

## 实验

生成 `PROJECT_MAP.md`：

```text
用户 → 入口 → 输入 → 处理 → 输出 → 保存/交付 → 验证
```

为每个节点标记：已有、需要现学、Agent 可直接完成、需要学生拍板、暂不需要。把危险项标红：秘密、个人数据、删除、写库、权限、付费服务。

## 证据

地图能解释第一刀从哪里进入、在哪里结束；没有列出与当前切片无关的技术全家桶。
