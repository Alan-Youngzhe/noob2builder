# 先做可见原型

## 目标

在大规模实现前，让学生看见并纠正产品方向。

## 讲授

原型不是为了把页面画漂亮，而是为了发现需求：信息顺序对不对、用户第一步做什么、成功和失败怎样反馈、哪些内容其实不需要。

先讨论一页 PRD 和最小 Design System：产品语气、颜色角色、字体层级、间距、组件状态。然后按环境选择：Lovable 快速生成可交互 Web 原型；baoyu-design 在本地 Agent 工作区生成 HTML；Figma/Pencil MCP 用于需要协作设计文件的场景。学生不用手画，但必须反馈和拍板。

## 实验

1. 收集 2–3 个相关参考，注明喜欢的是结构、交互还是视觉，不整站抄袭。
2. 输出最小 Design System。
3. 生成一个核心流程原型。
4. 检查默认、Hover/Focus、Loading、Empty、Success、Error、Disabled 中真正相关的状态。
5. 让目标用户或同学在不听解释的情况下指出下一步会点哪里。

## 证据

原型地址或本地文件、一次方向修改和明确拍板记录。原型代码不能未经检查直接当生产代码。
