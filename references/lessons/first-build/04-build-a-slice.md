# 敏捷开发一个端到端 MVP

## 目标

先用敏捷开发验证核心方案可行，让真实输入经过真实处理得到可见输出；不要在产品假设尚未验证时投入完整工程体系。

## 开始前

需要 Git 时插入 Git 最小节点；涉及 Web 时读取 `../shared/web-product-foundations.md`；涉及秘密和外部服务时读取安全节点。

## 讲授

实现循环保持很小：读 PRD v1、Design System、原型和 Spec → 实现一个垂直步骤 → 运行最低必要验证 → 查看 diff → 保存 commit → 再进入下一步。一次让 Agent 重写整个项目会放大错误并让人无法判断变化。

MVP 阶段优先回答“核心用户流程是否可行、有没有人需要”，暂不追求完整重构、全量测试矩阵和复杂 CI。但 API Key、隐私、危险写入、基本版本历史和核心流程 smoke 验收不能省。

## 实验

1. 创建或确认仓库和当前分支。
2. 把 MVP 砍成 3–5 个可独立验证的垂直步骤。
3. 每次只让 Agent 做一个步骤，并说明改了哪些文件。
4. 查看 diff；学生确认实现没有偏离 PRD v1 和原型。
5. 执行最低必要测试或行为检查后提交。
6. 出现冲突时升级为决策，不让 Agent 静默改产品目标。
7. 让学生和至少一位目标用户完成核心动作，记录是否达到可行性门。

## 证据

可读 commit 历史、最低安全与 smoke 验收、每步验证结果、端到端 MVP，以及“继续投入 / 修改方向 / 停止”的可行性判断。只启动开发服务器不算通过。
