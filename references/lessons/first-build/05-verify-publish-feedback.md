# 测试、修复、发布与第一位用户

## 目标

把本地 Demo 变成别人可以获得或使用的作品，并用真实反馈完成第一轮闭环。

## 讲授

发布方式由作品决定：网页可以部署，脚本可以打包并给运行说明，Skill 可以通过仓库或安装包分发，数据工具可以交付模板和样例。部署不是唯一发布方式。

上线前先跑三类验收：主路径、边界或失败路径、隐私与秘密检查。上线后重新从外部入口走一次；本地成功不代表生产环境的变量、权限、网络和数据都正确。

“有网址”不等于“有产品”。至少一位目标用户在不依赖作者代操作的情况下完成核心动作，才获得外部证据。

## 实验

1. 运行项目适用的真实测试和构建；保存退出结果。
2. 故意制造一个失败，确认界面或日志能暴露并恢复。
3. 选择最小交付方式并发布。
4. 从另一设备、无痕窗口或第二个用户入口验证。
5. 请一位目标用户完成核心动作，只记录必要反馈。
6. 根据反馈修复一项问题或明确拒绝一项无关需求。
7. 读取 `../shared/evidence-card.md` 生成证据卡。

## 证据

交付地址或使用说明、真实测试、失败修复、用户反馈和证据卡。外部服务不可用时只能标记 blocked，不能把本地页面写成已上线。
