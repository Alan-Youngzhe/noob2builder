# 写给 Agent 看的规格：TypeScript

## 目标

学生理解类型是"机器可检查的需求说明"：能看懂常见类型标注，会读类型报错，并能用一次类型错误证明它比肉眼更早发现问题。

## 讲授

TypeScript 是带类型的 JavaScript，浏览器不认它，构建时会被检查并转回 JS。`const name: string = 'alan'` 声明了"这个值只能是字符串"；函数参数和返回值的类型声明了"输入输出契约"。接口（`interface`）或类型别名描述一个对象必须有哪些字段。

对 Agentic Engineering 的价值是直接的：类型是写给 Agent 看的规格。Agent 改了数据结构，类型检查会把所有受影响的地方一次列出来，不靠人脑记忆。`npm run build` 或 `tsc --noEmit` 就是这道检查。

常见误区：用满屏 `any` 绕过检查（等于没写类型）；把类型报错当噪音关掉；以为类型能保证逻辑正确——它只保证形状一致。

## 实验

在上一课的 Vite 项目基础上（或新建 `--template vanilla-ts`）：

1. 把一个 `.js` 文件改成 `.ts`，给一个函数加上参数和返回值类型；
2. 故意制造一个类型错误：把字符串传给期望数字的参数。跑 `npx tsc --noEmit`，读报错——学生要能指出哪个文件哪一行、期望什么、实际给了什么；
3. 让 Agent 修复，学生确认检查重新通过；
4. 讨论：这个错误如果不用 TypeScript，会在什么时候、以什么形式暴露？（答案：运行时、可能是在用户面前。）

## 证据

一次"制造错误 → 类型检查报错 → 修复 → 通过"的完整记录；学生能用一句话向别人解释类型检查替他挡住了什么。
