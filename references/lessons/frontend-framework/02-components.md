# 组件化：props、state 与组合

## 目标

学生理解组件是"带输入和内部状态的界面积木"：能区分 props（外部传入）和 state（内部自管），能把一个页面拆成合理的组件，并说出拆分依据。

## 讲授

组件 = 一块可复用的界面 + 它的逻辑。props 是父组件传下来的输入，只读；state 是组件自己管理的数据，变了会触发重新渲染。一个页面就是一棵组件树，数据沿树向下流（props），事件向上冒（回调）。

拆分的判断标准不是"差不多大"，而是职责：这块界面是否有自己独立的数据和交互？是否在多处出现？超过一个屏幕的组件通常藏了不止一个职责。组件拆得好，Agent 改一个功能时 diff 就只落在该落的文件里——这是 Agentic Engineering 里组件化最实际的好处。

常见误区：把所有代码堆在一个巨型组件里；props 层层透传五六层（说明结构或状态位置有问题）；把可以计算出来的值也存成 state。

## 实验

在上一课的框架项目里做一个"待办清单"：`App` 包含输入框组件、列表组件、单个待办项组件。

1. 学生先画组件树，标出每个组件的 props 和 state 应该是什么（state 放哪一层是关键决策）；
2. 让 Agent 按这张图实现，学生对照检查：实现和图一致吗？不一致处谁更有道理，为什么；
3. 验收：新增、勾选、删除各操作一次，界面与控制台均无异常。

## 证据

一张学生画的组件树图（含 props/state 标注）；实现与图的对照结论；三个操作的真实行为证据。
