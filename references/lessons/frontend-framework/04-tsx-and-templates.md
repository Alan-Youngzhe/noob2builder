# TSX 与模板：类型安全的 UI

## 目标

学生能读懂 TSX（或 Vue 模板 + `<script setup lang="ts">`）文件的结构，理解"组件的 props 有类型"意味着什么，并体验一次类型在组件边界上挡住错误。

## 讲授

TSX = TypeScript + 类 HTML 标记，一个 `.tsx` 文件里既有 UI 结构又有逻辑和类型。组件的 props 用类型声明：`<Counter initial={0} label="数量" />` 中每个 prop 的名字和类型都是契约，传错在构建期就报错，而不是运行时才白屏。Vue 模板配合 `defineProps<{...}>()` 达到同样效果。

读一个组件文件的路数：先看 props 类型（它需要什么），再看 state（它管什么），再看返回值/模板（它长什么样）。这三眼读完，一个组件就懂了七八成——这也是 review Agent 生成组件的顺序。

常见误区：props 类型标成 `any`；把 TSX 里的 `{表达式}` 当成字符串插值而不是 JS 执行；看见类型报错就先 `as any`。

## 实验

在学生选定的框架项目里：

1. 给待办清单的 `TodoItem` 组件写出明确的 props 类型（`id: number`、`text: string`、`done: boolean`、回调）；
2. 故意在父组件里传错：把 `id` 传成字符串。跑构建/类型检查，学生读出报错并修复；
3. 学生练习"三眼读法"：挑一个 Agent 生成的组件，说出它的 props、state 和渲染结构。

## 证据

一次 props 类型错误被构建期拦下的记录；学生对一个陌生组件的"三眼"解读录音或笔记。
