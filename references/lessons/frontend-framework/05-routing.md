# 路由与页面组织

## 目标

学生理解单页应用里"多个页面"是路由切换出来的组件切换，能加一条新路由，并能解释 URL、刷新和导航之间的关系。

## 讲授

SPA 只有一个真实 HTML 页面，路由库（React Router / Vue Router）监听 URL 变化，决定渲染哪个页面组件。`/settings` 不是一个文件，是一条路由配置。嵌套路由让布局（导航栏、侧边栏）保持不动、只换内容区。

由此引出两个经典问题：直接刷新 `/settings` 时开发服务器能处理，但部署到静态服务器后可能 404——因为服务器上真的没有这个文件，需要配置回退到 `index.html`；浏览器前进后退本质是 URL 历史，路由库接管了它。

常见误区：用 `<a href>` 跳页面导致整页刷新（应用内应用路由库的 `<Link>`）；把页面组件写得巨大，不拆子组件；以为路由就是"页面文件放哪"。

## 实验

在项目里做三个页面：首页、清单页、关于页，带共享导航栏。

1. 学生先写路由表（路径 → 页面组件），让 Agent 按表实现；
2. 验证：点导航切换（无整页刷新）、直接输入 URL 访问、浏览器前进后退，三种进入方式行为一致；
3. 布置思考题（有部署条件就实测）：把这个 SPA 构建后丢到纯静态服务器，直接刷新子路由会发生什么？为什么？

## 证据

三种进入子路由方式的行为证据；路由表与实现的对照；刷新 404 问题的解释或实测结论。
