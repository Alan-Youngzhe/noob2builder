# 项目结构与一次真实重构

## 目标

学生掌握一个框架项目的常见目录约定，能判断文件该放哪，并指挥一次有验收证据的重构：拆分一个过大的组件，行为不变。

## 讲授

一个典型的 Vite + 框架项目：`src/` 下按角色分目录——`components/`（可复用组件）、`pages/` 或 `views/`（路由页面）、`api/` 或 `lib/`（请求与工具函数）、`App` 和 `main` 是入口。判断标准：新功能来了，"这个文件该放哪"有明确答案；一个文件超过一个屏幕还管多件事，就该拆。

重构 = 不改变行为的前提下改变结构。它的纪律是：先确认现在有可观察的验收基线（测试或人工操作清单），小步改，每步验证，diff 保持可读。Agent 做重构的风险是"顺手"改了行为——验收证据正是为这件事存在的。

常见误区：重构和需求改动混在一个 commit；没有基线就开工；拆分时改了交互细节没人发现。

## 实验

1. 在项目中找一个（或让 Agent 先造一个）超过 150 行、含输入区 + 列表 + 统计的页面组件；
2. 学生先写验收基线：三个核心操作的预期行为（可借助真实浏览器逐条确认）；
3. 指挥 Agent 拆成 `XxxInput`、`XxxList`、`XxxStats` 三个子组件，要求不改任何行为；
4. 逐条复测基线，看 diff：只有移动和接线，没有逻辑变化。若行为变了，回滚重来并记录。

## 证据

重构前后的行为对比（逐条基线复测结果）；一份只含结构变化的 diff；学生画出的项目目录结构图，含"新功能该加在哪"的说明。
