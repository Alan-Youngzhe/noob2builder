# GitHub 是协作现场

## 目标

分清 repo、Issue、branch、Pull Request、review 和 merge，并走一遍不影响正式项目的练习流程。

## 讲授

Issue 用来公开问题、目标和验收；branch 隔离一组工作；PR 把变化、原因和证据放到可以讨论的位置；review 检查实现和风险；merge 才把变化进入目标分支。

PR 不是“发给老板审批的附件”，而是一份带可重放 diff、自动检查和讨论记录的变更提案。PR 被提出不等于一定会被合并。

## 实验

1. 检查学生是否已有 GitHub 账号；注册和验证码由学生本人完成。
2. 在自己的练习仓库创建 Issue，写清目标、非目标和验收。
3. 建分支解决一个极小问题。
4. 推送并创建 PR，描述改了什么、怎样验证、还有什么未验证。
5. 阅读 Files changed；如果可用，请 Agent 做一次独立 diff 检查，但最终由学生确认意图。

## 证据

Issue URL、PR URL、diff 摘要和检查状态。私有仓库证据只保存 URL 或脱敏摘要，不擅自公开内容。
