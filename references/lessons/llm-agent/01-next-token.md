# 基础动作是接下一个 token，但不是随机接词

## 目标

学生能说清模型每一步在做什么，知道 token 大概怎么算、为什么直接影响钱，并理解它写出像样代码和编造不存在的函数出自同一个机制。

## 讲授

模型的基础动作只有一个：**根据前面所有内容，预测下一个 token**，输出一个概率分布，选一个接上去，再预测下一个。一次回答就是这个动作重复几百上千次。

**token 不是字，也不是词**，是模型的切分单位。记住这几个量级就够用：

- 英文大约 **4 个字符 ≈ 1 token**，1000 token ≈ 750 个英文单词；
- 中文大约 **1 个汉字 ≈ 1～2 token**，所以同样意思的中文比英文更费 token；
- 代码里的符号、缩进、括号各自都要占 token，一个 `{` 就是一个；
- `Hello, world!` 大约 4 个 token。

这套切分方法叫 BPE（Byte Pair Encoding），OpenAI、Anthropic、Google 各家的切法不完全一样，所以同一段文字在不同模型上算出来的 token 数会有出入。API 按 token 计费，输入和输出通常分开定价、输出更贵——这就是为什么"让它少废话"是真能省钱的。

关键在于："接下一个 token"不等于"随机接词"。概率来自海量文本训练，模型学到的是语言、代码和推理的统计规律。所以它能写出结构正确的函数——结构规律很强；但它也会写出一个名字很合理、实际不存在的 API——因为**"看起来最像正确答案"和"是正确答案"在这个机制下不是一回事**。

这就是幻觉的根源，也是本校那条铁律的根源：Agent 的肯定句只是待验证的自然语言，必须用真实运行结果验证。典型表现是它调用一个 `df.drop_duplicates_by()` 这种"听起来该存在"的方法，跑起来直接 `AttributeError`。

**temperature** 控制选择的随机程度：调低更保守稳定，调高更发散。Anthropic 的取值范围是 0–1，OpenAI 是 0–2，具体默认值以现场查证为准。同一个问题两次答案不同，多半来自这里，不是模型"改主意了"。

常见误区：以为模型内部有一个数据库在查；以为它"知道"自己不知道；以为把语气写得更肯定就能减少编造。

## 实验

1. 找一段学生自己写的中文文字，让 Agent 数出 token 数，再把它翻成英文数一次，对比两个数字，验证上面的量级说法；
2. 问一个它确实不知道的具体事实（比如你本地某个私有文件里的内容），观察它是拒答、反问还是编造；
3. 把同一个开放问题连问三次，对比三次回答的差异，让学生解释差异从哪来；
4. 让 Agent 写一段调用某个第三方库的代码，然后**实际运行**。如果它用了不存在的函数，把完整报错原文抄下来——这是本课最重要的证据。

## 常见误区

- 幻觉不是偶发 bug，是这个机制的固有代价，只能靠验证和工具接地来降低；
- 回答长不等于信息多，输出 token 还更贵；
- "请不要编造"能降低概率，不能消除。

## 证据

学生能用自己的话解释"为什么它会编造一个不存在的函数"，并提交第 4 步的真实运行结果——代码、命令和报错原文。第 1 步的两个 token 数字入档。
