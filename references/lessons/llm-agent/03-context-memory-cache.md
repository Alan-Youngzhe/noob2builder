# Context、Memory 与缓存：三个经常被混为一谈的东西

## 目标

学生能分清"这次请求带了什么"（Context）、"跨会话还留着什么"（Memory）和"为什么第二次更快更便宜"（缓存），并知道缓存不是记忆。

## 讲授

三个词各管各的事：

- **Context**：本次请求实际发出去的全部输入。有上限，叫 Context Window，用 token 计。超了就必须裁剪、摘要或分批。
- **Memory**：跨会话保留的信息。它不在模型里，在你这边——存成文件、数据库或规则文件，下次由客户端**主动放进 Context** 才生效。所谓"AI 记住了我的偏好"，实现上都是"某个程序把偏好读出来塞进了这次请求"。
- **缓存**：一种性能优化，让重复的输入不必重新计算。

缓存要再分两层：

- **KV Cache** 是生成过程内部的优化。模型逐 token 生成时，把已经算过的中间结果留着，避免每接一个 token 就把前文重算一遍。它服务于这一次生成。
- **Prompt Cache** 是跨请求的优化。当多次请求共享同一段很长的前缀（比如同一份 system 内容加同一批文件），服务端可以复用这段前缀的计算结果，从而更快、更便宜。它按前缀匹配，**改动越靠前，失效的越多**——所以稳定内容放前面、变动内容放后面是有实际收益的。缓存有有效期，Anthropic 的 Prompt Caching 默认是 5 分钟量级、另有更长的选项，具体时长和折扣以现场查证为准。

**关键判断：缓存命中不等于模型记得你。** 缓存省的是计算，内容仍然要在请求里完整送过去；缓存过期只是变慢变贵，不会导致"它忘了"。反过来，它"忘了"也不是缓存失效，是那段内容压根没进这次的 Context。

这个区分直接决定你怎么排查："它怎么不记得我说过 X"——去查 X 有没有进这次请求，而不是去研究缓存。

常见误区：把 Prompt Cache 当长期记忆；以为清缓存能让它"忘掉"敏感信息（要删的是存储和历史）；以为 Context Window 大就不用管长度（贵和注意力稀释仍然存在）。

## 实验

1. 让 Agent 说明当前模型的 Context Window 上限，并估算当前会话已用了多少；
2. 把同一份较长的资料连续问两次相似问题，观察第二次的响应时间差异，让 Agent 解释可能的原因，并明确标注哪些是推测；
3. 找出这台机器上真正承担 Memory 角色的文件，逐个打开看里面到底存了什么：`~/.claude/CLAUDE.md`（全局规则）、项目里的 `CLAUDE.md`（项目规则）、`~/.claude/skills/`（技能）、`~/.noob2builder/me.json`（本校学习存档）；
4. 修改其中一处，重新开一个会话验证改动是否生效——这一步证明的是"文件 → Context"这条链路，不是模型记忆；
5. 让学生用一句话回答："要让它下次还知道这件事，我该改哪个文件？"

## 常见误区

- 存档和规则文件里不要写 API Key、隐私和客户数据，理由见 `../shared/safety-and-secrets.md`；
- 响应时间受网络和负载影响，第 2 步的结论只能是"可能"，存档要标记为未验证；
- 摘要压缩会丢信息，长对话中的关键结论应该落到文件里，而不是指望历史一直在。

## 证据

学生能指出自己机器上一个真实的 Memory 载体文件，说明它是怎样进入 Context 的，并完成一次"改文件 → 新会话生效"的验证。
