# 你的数据走了哪条路：中转层、模型服务与合规边界

## 目标

学生能画出从自己电脑到模型的完整路径，知道中间可能有哪些环节，判断哪些内容不该发出去。

## 讲授

小白通常以为链路是"我 → 模型"。真实链路至少是：

```text
你的客户端（Claude Code / 某个 App）
→ 可能的中转层（第三方代理、聚合平台、公司网关）
→ 模型服务商 API
→ 模型
```

每多一个环节，就多一处能看见你输入内容的地方。这不是要吓人，是要能做判断：

- **官方 API**：直连服务商，条款和数据处理政策可查；
- **中转/聚合平台**：一个 Key 调很多模型、可能更便宜，但你的请求内容会经过它。是否记录、保留多久，取决于这家平台，通常不透明；
- **公司网关**：由公司控制，通常有审计，但也意味着可查。

小白最容易出事的两个动作：**把公司代码或客户数据粘进来图方便**，以及**为了便宜用来路不明的中转服务并把主力 Key 配上去**。

配套的是一条简单判断：**这段内容如果被第三方留存，我能接受吗？** 不能接受就不要发，或者先脱敏。

`base_url` 指向哪里，就决定了你的数据流向哪里。几个可以直接认脸的地址：

- `https://api.anthropic.com` —— Anthropic 官方，Claude 系列；
- `https://api.openai.com` —— OpenAI 官方，GPT 系列；
- 其它域名一律先问清楚是谁家的、条款在哪、是否记录请求内容。

Claude Code 里对应的环境变量是 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_API_KEY`，看不懂配置文件里的地址时，先问清楚再用。

常见误区：以为本地跑的 Agent 就是本地推理（Claude Code 是本地程序，推理仍在云端）；以为"不上传文件"就没发出去（Agent 读文件后内容照样进请求）；以为免费就没有代价。

## 实验

1. 打开当前 Agent 的配置（`~/.claude/settings.json` 或环境变量 `ANTHROPIC_BASE_URL`），找到它实际请求的地址，说出这是官方还是中转；
2. 让 Agent 列出这次会话中它读过的所有文件，学生逐个判断"这些内容我接受它离开本机吗"；
3. 用抓包或 Agent 自述之外的方式确认一次真实请求的目标地址——做不到时明确记为**未验证**，不要用 Agent 的说法冒充证据；
4. 检查 API Key 存在哪里，确认它没有出现在 Git 仓库、聊天记录或截图里，必要时读 `../shared/safety-and-secrets.md`；
5. 在 `MY_REQUEST_FLOW.md` 里补上这条数据路径，并标出你认为风险最高的一环。

## 常见误区

- Key 泄露最常见的方式是提交进 Git 和贴进群聊，不是被黑；
- 换模型不等于换服务商，也不等于换数据路径；
- 合规问题问的是"允不允许"，不是"技术上能不能"，遇到公司或客户数据时先确认授权。

## 证据

`MY_REQUEST_FLOW.md` 中有一条完整的数据路径图，标明中间环节和风险点；Key 存放位置经过检查且未进入版本库。无法证实的环节标记为未验证。
