# 它凭什么知道：训练、搜索与私有资料

## 目标

学生能分清模型的三种"知道"——训练时学到的、现场搜来的、从自己资料里检索到的——并知道各自会在什么地方出错。

## 讲授

同一个问题，模型可能通过三条完全不同的路径回答，可靠性也完全不同。

**一、训练时学到的（参数里的）**

模型训练有**知识截止日期**，截止之后的事它不知道。它不会告诉你"我不知道"，而是很可能按语言规律编一个像样的答案。所以问"最新版本是什么"这类问题，纯靠模型回答基本不可信。

**二、现场搜索（Web Search）**

Agent 发起一次真实搜索，把结果放进 Context 再回答。好处是能拿到新信息，代价是：搜到的网页本身可能是错的、过时的、或者是别人写的营销内容。**搜索把"编造"换成了"引用"，没有换成"正确"。**判断方法很朴素——看它给没给来源链接，点开看那个链接说的是不是这个意思。

**三、私有资料检索（RAG）**

RAG 是 Retrieval-Augmented Generation，检索增强生成。流程是固定的四步：

```text
把你的资料切成片段
→ 转成向量存进向量库
→ 提问时把问题也转成向量，找出最相近的几段
→ 把这几段塞进 Context，让模型基于它们回答
```

关键认知：**RAG 不是让模型"学会"了你的资料，它只是每次现找几段贴进 Context。**所以它会因为切片切错了、检索没命中、或者相关内容分散在十个片段里而答错。资料明明在库里却答不上来，通常问题出在检索那一步，不在模型。

对小白最实用的一条：资料不多的时候，**直接把文件读进 Context 比搭 RAG 更准也更简单**。RAG 是为了应付"资料量超过 Context Window"才存在的，不是必需的高级配置。

常见误区：以为搜索过就等于正确；以为把文档喂进去模型就"学会"了（那是微调，不是 RAG）；资料量只有几十页也急着上向量库。

## 实验

用同一个问题跑三遍，问题要选**模型截止日期之后、且你能自己核实**的事实：

1. **无工具**：让 Agent 关掉搜索直接回答，记录它说了什么、有没有表示不确定；
2. **搜索**：让它联网搜索后回答，记录来源链接，然后**真的点开那个链接**核对；
3. **私有资料**：把一份你自己的文件读进来，问一个只有这份文件里才有的问题；
4. 三个答案并排放，让学生标出各自的失效点：哪个是编的、哪个引用了不可靠来源、哪个受限于资料本身；
5. 把这一段补进 `MY_REQUEST_FLOW.md`：在你的链路图上标出这三条路径分别从哪进来。

## 常见误区

- 有来源链接不等于来源可靠，也不等于内容真的支持这句话；
- RAG 答错先查检索命中了什么，别急着换模型；
- 微调（fine-tuning）改的是模型参数，RAG 改的是 Context，两件事别混。

## 证据

三种路径的真实回答记录，其中至少一条被学生亲自核实过（点开链接或对照原文件）。学生能说出每条路径最可能在哪一步出错。
