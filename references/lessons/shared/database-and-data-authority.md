# 共享节点：数据库与数据权威源

## 什么时候加载

只有当前作品确实需要持久化、登录、多人共享数据、跨进程访问，或者已经出现“两个入口看到的数据不一致”时才加载。静态网页、一次性脚本和不需要保存状态的作品可以没有数据库。

## 小白先看懂一件事

数据库不是“项目显得完整必须安装的东西”，而是保存状态并让正确的人在正确时间读写它的系统。

先画真实链路：

```text
用户动作
→ 页面 / CLI / Desktop
→ API、IPC 或本机调用
→ 负责校验与权限的程序
→ 数据权威源
→ 结果返回用户
```

`localhost` 只说明服务运行在本机，不代表其他人能访问。Supabase 是包含托管 PostgreSQL 等能力的产品选择，不等于“数据库”这个概念本身。Docker 是运行软件的方式，也不是一种数据库。

## 先分清三个维度

| 维度 | 回答的问题 | 例子 |
|---|---|---|
| 数据模型 / 引擎 | 数据怎样组织、查询和约束 | PostgreSQL、MySQL、SQLite、MongoDB、Redis |
| 访问拓扑 / 部署形态 | 谁持有数据，其他进程怎样访问 | 进程内嵌入、权威进程 + IPC/API、独立数据库服务 |
| 运行与运维方式 | 它在哪里、由谁启动维护 | 本机二进制、Docker、云托管 |

不要把不同维度放在一张候选表里直接比较。例如“MongoDB 还是 Docker”不是一道有效的选型题。

## 四个问题决定第一版

按顺序回答，不从产品排行榜开始：

1. **需要保存吗？** 关闭程序或换一台设备后，数据是否还要存在并被找回？
2. **谁会访问？** 只有一个本机用户，还是多个用户、进程或机器？
3. **数据是什么形状？** 是否需要结构化字段、关联、事务、搜索、缓存或语义检索？
4. **谁来运维？** 学员自己、本地终端用户、团队，还是云平台？成本、备份、迁移和恢复由谁负责？

先选择能完成当前核心行为的最小方案，并写一个备选。不要因为“以后可能需要”提前加入登录、Redis、向量库、消息队列或复杂集群。

## 数据只有一个逻辑权威源

同一份业务数据必须有一个能回答“最终以谁为准”的权威源。多个页面、服务和客户端可以访问它，但不能各自悄悄维护一份真实数据，再期待它们自动一致。

这里的“一个”指一个逻辑真相来源，不等于数据库只能由一个进程打开：

- SQLite 支持多个进程打开和读取同一文件，但同一时刻只有一个写入者；文件锁、并发量和文件系统环境会影响是否适合。
- PGlite 核心是单连接形态；需要多连接时可调查权威进程、Socket Server 或正式 PostgreSQL，不能让每个进程各建一个实例后假装它们共享数据。
- 多用户 Web、跨机器访问、高并发写入或统一权限控制，通常更适合 client-server 或云托管数据库。
- Redis 可以持久化，也可以承担主数据角色；但普通 Builder 项目默认把它当缓存、队列或锁，除非能解释数据模型、恢复与内存成本。

技术选型不是铁律。Web 协作产品可以优先调查 PostgreSQL；单机 CLI、桌面工具或低并发本地应用可以优先调查 SQLite/PGlite；没有持久化需求就先不加数据库。

## Alan 的真实事故：Ordine PGLite 双实例

Ordine 开发环境曾出现 App 与 Server 数据不一致。问题不是“PGLite 太轻”，而是两个进程分别 import 数据库模块，各自创建 PGLite 实例；相对路径又按不同工作目录解析，最终落到两个物理数据目录。部分 API 写 Server 的库，其他路由和认证写 App 的库，同一领域数据被分裂成两份。

团队确认开发环境具备 Docker、项目需要多进程共享数据后，改为一个通过 `DATABASE_URL` 访问的 PostgreSQL 服务。这个案例形成的判断是：

> 先画清进程和数据流，指出唯一权威源，再讨论引擎与运行方式。不要把一次事故扩大成“所有嵌入式数据库都不能多进程”的伪定律。

## 实验

1. 为当前作品画一张进程与数据图，标出浏览器、SSR、API、Desktop/CLI、数据库和外部服务。
2. 给每条读写路径写明：谁发起、经过哪里、最终写到哪里、失败怎样被发现。
3. 圈出唯一逻辑权威源；如果存在两份都自称真实的数据，先修架构再选品牌。
4. 让 Agent 给出最小方案和一个备选，分别说明适用条件、暂不需要什么、迁移与恢复方式。
5. 用两条真实入口写入和读取同一条测试数据；重启相关进程后再次读取。不能只看 HTTP 200 或 Agent 的“成功”。

## 完成证据

- 一张能解释进程、传输和权威源的数据流图；
- 一份选型记录，分开写引擎、访问拓扑和运行方式；
- 至少一次真实写入、跨入口读取与重启后读取证据；
- 已记录备份、迁移、恢复、秘密和个人数据边界；
- 学生能解释为什么当前方案适合，而不是只说“大家都用它”。
