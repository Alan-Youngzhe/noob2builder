# 为什么测试：让“完成”变成证据

## 目标

理解测试不是给代码贴勋章，而是把一个可观察行为变成可重复检查的证据。

## 讲授

Agent 说“已经修好”“测试通过”都只是待验证的自然语言。真正的证据至少包括：测试输入、运行命令、退出码、断言结果、环境和未覆盖风险。

先分清三个词：

- **验收标准**：产品必须表现成什么样；
- **测试**：怎样用机器或真实用户动作检查它；
- **Review**：另一个人或 Agent 是否发现了测试没有覆盖的风险。

不要一开始就问“用 Jest、Vitest 还是 Pytest”。先从一条行为写出：

```text
Given：报名页面输入了合法姓名和手机号
When：用户提交表单
Then：系统创建一条报名记录，并显示成功状态
```

## 实验

1. 从当前项目选一条真实核心行为。
2. 写一个正常、一个边界、一个失败场景。
3. 让 Agent 为每个场景推荐最低成本的证据类型，并说明不能证明什么。
4. 实际运行其中一个检查，记录命令和结果。

## 常见误区

- 测试文件存在不等于测试运行过；
- HTTP 200 不等于业务动作成功；
- 覆盖率高不等于关键风险被保护；
- 同一个 Agent 写代码、写测试、自己宣布通过，不等于独立验证。

## 证据

提交一份 `TEST_EVIDENCE.md`，包含行为、命令、退出码、结果、环境和未验证项。
