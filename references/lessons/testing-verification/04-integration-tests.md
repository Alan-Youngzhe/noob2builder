# 集成测试：保护模块边界

## 目标

验证多个真实模块连接后仍然符合合同，例如 API、数据库、文件系统或消息队列之间的输入输出。

## 怎么写

以报名 API 为例：

```text
POST /registrations
→ 校验请求
→ 写入独立测试数据库
→ 返回 201
→ 再查询数据库，确认记录确实存在
```

集成测试可以使用临时数据库、测试容器或项目已有的测试环境，但不能使用生产数据库、真实用户数据或真实支付副作用。

## 必须检查的边界

- API 字段与数据库字段是否一致；
- 迁移是否已执行；
- 权限是否在服务端真正生效；
- 重复提交和事务失败是否可恢复；
- 外部服务超时或返回错误时，系统是否诚实降级。

涉及数据库时加载 `../shared/database-and-data-authority.md`；涉及 HTTP 状态和联调时加载 `../shared/http-status-codes.md`。

## 证据

一条真实集成测试命令、独立测试数据、写入后查询结果、失败路径和清理方式。不能只断言 HTTP 200。
