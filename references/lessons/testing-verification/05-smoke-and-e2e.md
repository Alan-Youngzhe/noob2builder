# 冒烟与 E2E：保护真实路径

## 冒烟测试

冒烟测试是一小组快速、关键、广而浅的检查，用来判断版本是否值得继续深入测试：

```text
GET /                 → 200
GET /api/health       → 200
合法提交一条报名       → 201
刷新管理页面           → 能看到这条报名
```

冒烟失败时先停止发布和复杂调试，修复最基本的断裂。

## E2E 测试

E2E 模拟用户从头到尾完成一条任务：打开页面、输入、点击、观察状态，再检查最终结果。它最接近真实体验，但速度慢、定位成本高、容易受浏览器、网络和测试数据影响。

适合 E2E 的是少数高价值旅程：注册、登录、报名、核心交易、权限边界和发布后的关键入口。手机号格式这种细节应留在单元测试，不要全部搬进浏览器。

## 实验

1. 先写一组 API 或命令行冒烟检查。
2. 再挑一条最关键用户旅程做 E2E 或真实浏览器验收。
3. 观察默认、加载、空、成功和错误状态。
4. 让测试失败一次，确认错误能定位到请求、页面或服务端，而不是只显示“失败”。

## 证据

保存冒烟命令、E2E/浏览器操作记录、环境、测试数据、失败截图或日志以及修复后复测结果。
