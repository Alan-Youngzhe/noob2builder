# 回归、Mock、Flaky Test 与覆盖率

## 回归测试

每次修复一个真实 Bug，都把“原来怎样失败、现在怎样通过”固定成测试或可重复检查。以后再改代码时，这条测试就是护栏。

## Mock 的边界

Mock 适合隔离昂贵、不稳定、不可控的外部依赖；但不要把内部核心链路全部 Mock 掉。否则单元测试全绿，真实 API、数据库和权限仍可能完全不可用。

## Flaky Test

偶尔失败的测试不是“多重试几次”就算解决。排查共享状态、时间依赖、随机数、网络、并发竞争和测试顺序。重试最多是临时诊断手段，不能掩盖不稳定。

## 覆盖率

覆盖率只能回答“哪些代码被执行过”，不能回答“关键结果是否被正确断言”。优先保护核心行为、历史 Bug、高风险路径和失败处理。

## 其它常见误区

- 用测试数量代替风险分析；
- 只测正常输入，不测空值、边界、重复、越权和超时；
- 测试实现细节，导致重构时无意义地大面积失败；
- 同一个 Agent 写代码、测试、Review 并宣布完成；
- 删除失败测试，而不是判断代码还是测试谁错了。

## 证据

对当前项目挑一个失败或不稳定测试，记录复现、根因、修复、重跑和相邻回归结果。
